# Code

The programs that produced the rules and checked them numerically, as published on the original atlas page. Their floating-point Newton–Kantorovich test is a numerical check, not a proof; the proofs come from `tools/verify_rigorous.py`. They need numpy and scipy.

`cubature_search.py` (version 3) produced the cube rules CA-C3-21-486 … CA-C3-30-1324. It searches in a chosen subgroup of the cube group (Oh, Td, Th, O, T, …): orbit elimination, large-neighbourhood search with simulated annealing, a rank-ILP target structure, and warm starts from stored rules (`--refine T --sources dir`). Run `python3 cubature_search.py --help` for the options; the module docstring describes the method and lists the literature.

## Design rules for `cubature_generic.py`

`cubature_generic.py` is a generic solver. Changes to it follow these rules (set by the maintainer):

- Rules may depend on the domain (cube, simplex), on the dimension, and on the degree modulo a small number (for example odd and even degree). They must not depend on individual degrees or node counts: no tables of special cases per degree, no hand-picked starting points for one configuration.
- The start must converge directly. No node removal or node elimination, no continuation from a rule with more nodes, no long trial-and-error over many starts.
- Main goal: in the most common configurations, find a rule with at most Z nodes quickly. Z = ceil(M / (d + 1)) with M the number of moments; on square and cube Z is the smaller of this and ceil(2 E / (d + 1)), E the number of moments of even degree (the count of a centrally symmetric rule), as on the website. The minimal node count is not required for every configuration.

### Start on the square: angle lattice

For C4, C2 and no symmetry on the square the start is a lattice in the angle coordinates theta = arccos(-x) (spectrum |k|_1 <= n of a cosine polynomial, hence a 45 degree checkerboard lattice):

- spacing h = pi / sqrt(2 N), lattice points h (a, b) with a + b even (centre point, N odd) or odd (hole, N even);
- rotation by alpha = 2 delta / pi, delta the boundary distance of the unrotated lattice; the rotation runs along concentric squares (every point slides along its L_inf shell by alpha / (2 pi) of the perimeter), so rows near a side move parallel to it and keep their boundary distance; C4 and C2 stay exact;
- without symmetry the lattice is also shifted by a quarter point spacing in x, scaled per coordinate by the distance to the boundary (full at the centre, zero at the boundary);
- surplus orbits are removed nearest to the corners (the centre first if the surplus is odd); missing orbits (the centre first if the deficit is odd) go greedily, each to the candidate farthest from all points (the boundary counting as a mirror), but only on few lines: with C4 on the line between the outermost and the second outermost L_inf shell (all four sides), with C2 on the line through the centre parallel to a side; only when these lines are full (best distance below 0.7 h) the next line is opened (C4: the mid line one shell further in; C2: the parallel lines at +-2 h, +-4 h, ...); without symmetry the missing points go into the largest gaps of the whole square;
- these three groups start at N = Z.

### Run time

The solver is sensitive to rounding: a change of the evaluation order at the level of 1e-16 can turn a converging start into a failing one (and the other way round). Changes that only make it faster must therefore give bitwise identical results (same log, same rule files); check this on a few cells before and after the change. Most of the time at high degree goes into the number of LM runs of the ladder (every N, every group, 12 to 16 starts) and into the O(M_G^3) linear algebra of each step; `--single-start` needs one start per group.

The rule files in `rules/` are the authoritative data. The build (`tools/build_atlas.py`) checks them independently of this code.
